3 steps to fix MCP context bloat immediately

  1. Audit active tool count with /context. Any project loading over 25 MCP tools is burning 12K+ tokens on tool schemas alone before reading a single source file.
  2. Move global servers into project .mcp.json. Keep global MCP config empty and enable only the 1 or 2 servers each repository actually requires.
  3. Prefer native CLIs over MCP wrappers. Tools like gh, git, rg, and psql cost 0 schema tokens and execute faster than JSON-RPC MCP bridges.

Common questions

Why do MCP servers cause context bloat in Claude Code?

Every enabled MCP server registers its full JSON schema (tool name, description, and nested parameters) inside the system prompt on every API turn, consuming 350 to 1,000 tokens per tool.

Does prompt caching eliminate MCP context bloat?

Prompt caching cuts the dollar cost of re-reading schemas by 90%, yet the tokens still occupy your 200K context window and degrade tool-selection accuracy.

How many MCP tools should be active in a single workspace?

Keep 8 to 15 high-impact tools active per workspace. That caps schema overhead under 7K tokens (3.5% of context) while keeping tool calls sharp.
