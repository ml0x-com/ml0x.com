How Anthropic prompt caching shapes your Claude Code bill

On every Claude Code turn, Anthropic bills uncached input tokens at 1.0×, cache-write tokens (5-minute TTL) at 1.25×, and cache-read tokens at 0.10× (a 90% discount). Because a typical coding loop keeps 80%–92% of the prefix warm across turns, prompt caching is the single biggest lever on cost — right alongside compacting sessions before context crosses 100K tokens and routing lint/test/format turns away from Opus.

Frequently asked questions

How much does a typical Claude Code session cost on the API?

A 35-turn Sonnet 4 session averaging 48K context with an 85% prompt cache hit rate costs roughly $1.60-$2.10. Running that exact same session on Opus 4 costs ~$8-$10.50.

When is Claude Max ($100 or $200/mo) cheaper than paying per token?

If you run more than ~50-60 Sonnet sessions per month (about 2-3 sessions per working day), your API spend crosses $100/mo. Heavy daily Opus users cross the $200/mo Max break-even in under 25 sessions.

Why do long Claude Code sessions get exponentially more expensive?

Every turn re-reads the entire conversation history. Even at the 0.10x cache-read rate, letting context grow from 40K to 160K tokens quadruples your input read cost per turn. Running /compact or starting a fresh session with a handoff file cuts cost by 50-70%.

How much does hybrid model routing save?

Using Opus only for architecture/review (15% of turns), Sonnet for implementation (65%), and Haiku for linting/tests/summaries (20%) cuts monthly API spend by 55-70% compared to pure Opus while keeping architectural quality intact.

How can I enforce a hard dollar cap on Claude Code?

Claude Code hooks (PreToolUse / PostToolUse) can read the session transcript token ledger and block further tool calls once spend hits your cap. Our $29 Claude Code Workflow Pack includes a ready-to-drop cost_guard.py hook with 64 passing tests.
