4 prompt caching architecture rules for 2026

  1. Order prompts strictly from static to dynamic. Place system prompt, tool definitions, and stable repo docs first; keep timestamps, git diffs, and user messages at the very bottom.
  2. Use 5-minute TTL for active coding loops. The 1.25x write breaks even after just 1 cache read (2 total turns). Reserve 1-hour TTL (2.0x write) for slow human-in-the-loop reviews.
  3. Stop mutating tool lists mid-session. Toggling an MCP server or editing system instructions mid-thread invalidates every downstream cache breakpoint.
  4. Monitor cache read-to-write ratio. Healthy coding sessions maintain at least an 8-to-1 ratio of cache read tokens to cache creation tokens.
